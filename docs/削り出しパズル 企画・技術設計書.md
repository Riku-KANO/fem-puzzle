# 削り出しパズル 企画・技術設計書

Oct 12, 2026 · @Riku KANO

## 概要

荷重のかかった3Dブロックを削り、壊れないギリギリの最軽量構造を彫り出すブラウザ用パズルゲームです。削るたびに裏で本物の有限要素解析(3D線形弾性)が走り、応力の流れが色で見えます。仮題は『応力彫刻 STRESS CARVE』とします。

- **体験の核**: 削ると応力の流れが組み変わり、最後に骨やアーチのような形が自分の手で浮かび上がる発見
- **プラットフォーム**: PCブラウザ(マウス操作)、インストール不要。スマートフォンは拡張フェーズで検討
- **ターゲット**: パズル好き、ものづくり・構造に興味がある層。FEMの知識は不要で、遊ぶうちに応力の流れが直感でわかるようにする
- **差別化**: 橋づくり系ゲームの多くは梁・トラスの組み立てだが、本作は連続体(ソリッド)を削る。穴や肉抜きの形そのものが答えになる

## コアゲームプレイ

1手ごとに「削る → 再解析 → 応力を見る」を回し、許容応力を守ったまま体積率を下げた人が勝ちです。

### 1ステージの流れ

1. ステージ提示: 設計領域(ボクセルの塊)、支点、荷重の向きと大きさ、目標体積率が示される
2. 削る: ボクセルをクリックまたはドラッグで除去する
3. 再解析: 削った直後に自動でFEMが走り、応力カラーマップが更新される(収束途中の結果も逐次表示)
4. 試験: 「載荷テスト」ボタンで荷重をかけ、変形を誇張したアニメーションで見せる
5. 判定と提出: 条件を満たした状態で提出すると星評価。最後に最適化アルゴリズムの解と並べて比較する

### 操作

| 操作 | 入力 | 内容 |
| --- | --- | --- |
| 削る | 左クリック / ドラッグ | 表面のボクセルを除去。ブラシは1、3×3、5×5の3段階 |
| 戻す | Ctrl+Z / 右クリック | 直前の削除を取り消す(履歴は無制限) |
| 視点 | 右ドラッグ / ホイール | 回転・ズーム。ダブルクリックで注視点を移動 |
| 断面 | スライダー | クリッピング平面で内部の応力を見る |
| 載荷テスト | スペースキー | 変形アニメーションと崩壊判定の演出 |

### 判定条件

- **強度**: 全要素の最大von Mises応力が許容応力以下
- **連結**: すべての荷重点が残った材料を通って支点につながっている
- **剛性**(ステージにより): 荷重点の変位が上限以下
- **保護領域**: 荷重点・支点の周囲は削れない(色を変えて表示)

### スコア

- 主スコアは残存体積率(低いほど良い)。目標値に応じて星1〜3
- 副指標として「最適化解との差」を表示し、アルゴリズムを上回ったら特別表示
- 応力が許容値を超えた状態で載荷テストをすると、超過した要素から崩れる演出を入れる(ペナルティではなく、どこが弱いかを教えるフィードバック)

## ステージ設計とゲームモード

薄い板状の「ほぼ2D」から始めて、ねじりや複数荷重など3Dでしか起きない問題へ段階的に広げます。

| ワールド | テーマ | 新しく覚えること | 想定グリッド |
| --- | --- | --- | --- |
| W1 工房入門 | 片持ち梁(薄板) | 応力の色の読み方、荷重点から支点への流れ | 24×8×4 |
| W2 橋 | 単純支持梁・アーチ | 中央荷重で中立軸付近が削れる理由 | 32×8×8 |
| W3 立体 | 3D片持ち・ねじり | 奥行き方向の肉抜き、中空断面の強さ | 32×12×12 |
| W4 嵐 | 複数荷重ケース | 重力と風の両方に耐える(全ケースで判定) | 40×12×12 |
| W5 合金 | 2種類の材料 | 硬いが重い材料と軽いが弱い材料の使い分け | 40×12×12 |

難易度は3つのつまみで調整します。

- **目標体積率**: 星3の目標を最適化解の体積率+5%程度に置くと、上級者が最適解に挑む余地が残る
- **許容応力の余裕**: 序盤は余裕を大きく、後半ほど最適解に近い形しか通らない
- **保護領域と障害物**: 削れない柱や穴あけ禁止区域で、教科書通りの解を崩す

### ゲームモード

- **キャンペーン**: W1〜W5の固定ステージ。各ワールド8〜10ステージ
- **デイリーチャレンジ**: 日付をシードに荷重・支点をブラウザ内で生成。全員が同じ問題を解き、記録は自分のブラウザに保存。結果は画像とテキストでSNSに共有できる
- **サンドボックス**: 荷重・支点・設計領域を自由に置き、作ったステージはURLに圧縮して埋め込んで共有(サーバー不要)
- **アルゴリズム対決**: 同じ問題をSIMP法が解いていく様子と並走し、どちらが軽く作れるかを競う

## 3D表現・UI/UX

3Dの難しさは「内部が見えない」ことなので、応力を内側まで読ませる表示を最優先にします。

### 応力の可視化

- **カラーマップ**: 要素ごとのvon Mises応力を許容応力で割った値(利用率)で塗る。0%は青、100%で赤、超過はマゼンタで点滅。色覚多様性向けにviridis系パレットも用意
- **断面ビュー**: クリッピング平面をスライダーで動かし、内部の応力を見せる。3軸それぞれに切り替え可能
- **X線モード**: 低応力の要素を半透明にして、荷重が通っている経路だけを浮かび上がらせる
- **主応力線**(拡張): 引張と圧縮の流れを線で描き、どこが「効いている」かを直感的に示す
- **変形表示**: 変位を数十〜数百倍に誇張してたわみを見せる。倍率は自動調整

### 演出

- 削ったボクセルは小さな破片になって落ち、作業台に積もる
- 載荷テストでは荷重治具がゆっくり降りて、たわみがアニメーションする
- 超過時はひびのデカールを出してから、超過要素から順に崩れる
- クリア時はカメラが一周して完成形を見せ、最適化解と半透明で重ねて比較する

### 画面構成

- **中央**: 3Dビュー(作業台の上の設計領域)
- **左上**: ステージ名、目標体積率と現在値のメーター、星の閾値
- **右**: 応力の凡例、最大利用率、表示モード切り替え(通常 / 断面 / X線)
- **下**: ツールバー(ブラシサイズ、Undo、載荷テスト、提出)

カメラはオービット操作を基本にし、初期視点は荷重と支点が両方見える斜め上45°に固定します。

## 技術アーキテクチャ

FEMソルバーをWeb Workerで動かし、削るたびの再解析中も描画と操作を止めない構成にします。

&#91;embedded content: システム構成 · メインスレッド、Worker、オフライン工程\]

メインスレッドからは削った要素の差分だけを送り、Workerは変位と応力(収束途中の結果を含む)を返します。

### 技術スタック

| 層 | 採用 | 理由・備考 |
| --- | --- | --- |
| 描画 | Three.js | glTF読込、InstancedMesh、クリッピング平面が揃っている |
| UI | HTML/CSS + 軽量フレームワーク(Svelte、Preact など) | 3D外のメーター類はDOMの方が作りやすい |
| ソルバー | Rust → WASM(SIMD128有効、wasm-bindgen) | GCがなく数値ループが速く、バイナリも小さい。効率を最優先してGo・TinyGoより優先 |
| 並列化 | Web Worker + wasm-bindgen-rayon によるマルチスレッド | SharedArrayBufferが必要。Cloudflare Pagesの `_headers` ファイルでCOOP/COEPを設定する([参考](https://dev.to/sike_ren_f38951df83469817/why-sharedarraybuffer-forced-me-to-delete-every-third-party-script-on-my-site-4fa6)) |
| 破片の物理 | Rapier(WASM) | 演出専用。FEM解析とは独立させる |
| 配信 | Cloudflare Pages(静的ホスティング) | サーバーなし。記録はブラウザ内に保存し、ランキングは当面設けない |

### ソルバー設計

- **要素**: 8節点六面体(Hex8)。全ボクセルが同じ形なので、要素剛性行列Ke(24×24)は1つを使い回せる
- **削除の扱い**: 要素を消さずにヤング率を極小値に下げる(ソフトキル)。さらに削除要素にしか接していない節点は解から外し、剛性差による条件数の悪化を防ぐ
- **解法**: 幾何マルチグリッド前処理付き共役勾配法(MGCG)。構造格子なので、粗いレベルは2×2×2の要素をまとめて作れる。最細レベルは行列フリー、最粗レベルだけ行列を組んでコレスキー分解で直接解く
- **SIMDとスレッド**: 要素ループの行列ベクトル積をWASM SIMD(f64x2)で計算し、要素ループは色分け(グラフ彩色)して複数スレッドで競合なく足し込む
- **精度**: CPU版は倍精度。WebGPU版を作る場合は単精度とし、収束判定の許容誤差を合わせて調整する
- **warm start**: 直前の変位を初期値にする。1手の変更は局所的なので、反復回数をさらに減らせる見込み
- **逐次表示**: 一定反復ごとに途中解を描画側へ送り、応力が落ち着いていく様子をそのまま演出にする
- **後処理**: 要素中心でひずみから応力を求め、von Mises応力を計算。連結判定は残存ボクセルの幅優先探索
- **ベンチマーク解**: 同じRustソルバーをネイティブビルドし、SIMP法とOC法でステージ作成時にオフライン計算してステージデータに同梱する(ゲームと最適化でコードを共有)

解く方程式と、材料の扱い(プレイヤーは ρ = 0 か 1、SIMP法は 0〜1 の連続値)は次の通りです。

```latex
K(\rho)\,u = f, \qquad E_e = E_{\min} + \rho_e^{\,p}\,(E_0 - E_{\min})
```

```latex
\sigma_{vm} = \sqrt{\tfrac{1}{2}\left[(\sigma_x-\sigma_y)^2+(\sigma_y-\sigma_z)^2+(\sigma_z-\sigma_x)^2\right]+3\left(\tau_{xy}^2+\tau_{yz}^2+\tau_{zx}^2\right)}
```

実装の下敷きには、Andreassenらの88行トポロジー最適化コード(2D、2011年)、Liu・Tovarの3D版top3d(2014年)、トポロジー最適化向けのマルチグリッドCGを扱ったAmirらの論文(2014年)が使えます。

## Blenderアセットパイプライン

Blenderは「見た目の素材づくり」と「ステージ作成ツール」の2役で使い、削られるブロック本体は実行時にコードで生成します。

### Blenderで作るもの

- **環境**: 工房の作業台、壁、照明。ローポリにライティングをベイクして軽くする
- **治具**: 支点(クランプ、ピン)と荷重治具(おもり、油圧シリンダー)。荷重の向きが一目でわかる形にする
- **演出素材**: 破片、ひびのデカール、作業台に積もる削りくず
- **UIアイコン**: 3Dでモデリングしてレンダリングし、PNGで使う

### ステージ作成フロー

1. Blenderで設計領域の形を普通のメッシュとして作る(L字、穴あき板など)
2. 命名規則で役割を付けたオブジェクトを置く: 支点 `support_*`、荷重 `load_*`(向きと大きさはカスタムプロパティ)、保護領域 `keep_*`、障害物 `block_*`
3. Pythonスクリプトで設計領域をグリッドにボクセル化し、ステージJSONに書き出す
4. 同じJSONをオフラインのSIMP最適化にかけ、ベンチマーク解と目標体積率を追記する
5. 環境アセットはglTF(.glb)で書き出し、Draco/meshopt圧縮をかける

ステージJSONは次のような形を想定しています(値は例)。

```json
{
  "id": "w1-03",
  "grid": [24, 8, 4],
  "voxelSize": 0.01,
  "material": { "E": 70e9, "nu": 0.33, "allowable": 120e6 },
  "solid": "<設計領域のビットマスク(base64)>",
  "keep": "<保護領域のビットマスク(base64)>",
  "supports": [{ "face": "x-", "fix": "xyz" }],
  "loads": [{ "cells": [[23, 0, 0], [23, 0, 3]], "force": [0, -500, 0] }],
  "targets": { "star1": 0.70, "star2": 0.55, "star3": 0.45 },
  "benchmark": { "volume": 0.41, "solid": "<最適化解のビットマスク>" }
}
```

### 書き出しの約束

- 単位はメートル、座標はglTFの規約に合わせてY-up
- ステージの一括ビルドは `blender -b -P export_stage.py` のようにコマンドラインで回し、CIに載せられる形にする
- 逆方向として、プレイヤーの完成形をSTLやglTFで書き出せるようにすれば、Blenderでの仕上げや3Dプリントにも回せる

## 性能見積もりと制約

マルチグリッド前処理CG(MGCG)を最初から採用し、W4・W5規模(約6,000要素)まで1手0.5秒以内を狙います。下表は比較の基準として、単純なJacobi前処理CGで見積もった机上の値です。Phase 0のベンチマークで置き換えます。

| グリッド | 要素数 | 自由度 | 1反復の演算量 | Jacobi CGでの1手(概算) | 想定ステージ |
| --- | --- | --- | --- | --- | --- |
| 24×8×4 | 768 | 3,375 | 約0.9 MFLOP | 0.09〜0.18秒 | W1 |
| 32×8×8 | 2,048 | 8,019 | 約2.4 MFLOP | 0.24〜0.47秒 | W2 |
| 32×12×12 | 4,608 | 16,731 | 約5.3 MFLOP | 0.5〜1.1秒 | W3 |
| 40×12×12 | 5,760 | 20,787 | 約6.6 MFLOP | 0.7〜1.3秒 | W4・W5 |
| 60×20×20 | 24,000 | 80,703 | 約28 MFLOP | 2.8〜5.5秒 | サンドボックス(大) |

前提: 自由度 = 3 ×(節点数)、1反復 = 要素ごとに24×24の行列ベクトル積(約1,152演算)、WASMの単一スレッド実効性能を0.5〜1 GFLOP/s、warm start後の反復回数を100回と仮定。MGCGでは1反復の費用が数倍に増える一方、反復回数は数十回以下に減る見込みで、SIMDとマルチスレッドを合わせると表の値から数倍〜一桁の短縮を期待しています。

### 高速化の打ち手(効果が大きい順の見込み)

- **マルチグリッド前処理**(採用): 反復回数を大きく減らす本命の手
- **空洞の自由度を除外**(採用): ソフトキルによる条件数の悪化を防ぐ
- **SIMDとマルチスレッド**(採用): 要素ループをf64x2で計算し、彩色した要素群を複数スレッドで並列に処理
- **逐次表示**(採用): 0.5秒を超える場合も、途中解を流して計算中の様子を演出として見せる
- **WebGPU計算**(Phase 3): 行列フリーの要素ループはGPU向き。対応ブラウザのみで使い、非対応時はWASMに戻す

### 描画とメモリ

- ボクセルは隣接面を間引いた外皮メッシュにし、削った周辺のチャンクだけを再生成する
- 8万自由度でも倍精度ベクトル1本は約0.65MBで、CGに必要な数本を合わせてもメモリは問題にならない

## リスクと決定事項

最大のリスクは「解析としては正しいが、ゲームとして理不尽に見える判定」です。応力特異点とボクセルの粗さへの対策を、判定ルールに最初から組み込みます。

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 応力特異点 | 荷重点や凹角で応力がメッシュ依存で跳ね上がり、判定が理不尽になる | 荷重を面に分布させる。保護領域は判定から除外。凹角には許容値の余裕を持たせる |
| ボクセルの粗さ | 1ボクセル厚の部材は応力の精度が低い | 最小肉厚2ボクセルのルール(下回ると警告表示)と判定の余裕 |
| 解析の待ち時間 | 削ったときの手応えが悪くなる | 逐次表示、マルチグリッド前処理、ステージごとのグリッド上限 |
| 最適形状の暗記 | 「骨っぽい形」を真似るだけで解けてしまう | 複数荷重、保護領域、障害物で毎回違う答えになるよう設計 |
| 応力表示の難しさ | 初見で何をすればよいかわからない | W1をチュートリアル化。利用率を%で表示し、低応力域を光らせるヒント |
| WASMの初回ロード | 起動が重くなる | Rustとwasm-optでの縮小、遅延ロード、圧縮配信 |
| ブラウザ差 | WebGPUやSharedArrayBufferが使えない環境がある | WASM単一スレッドを基準性能とし、拡張機能は上乗せに限る |

### 決定事項

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| タイトル | 『応力彫刻 STRESS CARVE』 | 削る行為と応力の可視化が一言で伝わる |
| ソルバー | Rust → WASM、MGCG、SIMDとマルチスレッド | 効率を最優先。オフラインの最適化ともコードを共有できる |
| 材料定数 | 内部はアルミ合金相当の実在値で計算し、画面では利用率(%)と星で見せる | 実在感を保ちつつ、単位を知らなくても遊べる |
| 公開形態 | Cloudflare Pagesで静的公開。ランキングサーバーは当面なし | 運用コストがかからない。記録はブラウザ内に保存 |
| スマートフォン | MVPはPCのみ。Phase 3でタッチ操作に対応 | 細かいボクセル選択はマウス前提で設計する |
